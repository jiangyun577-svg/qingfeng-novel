## 1. 项目与作者

- **作品**：《末世清风》，末世 + 重生流网文。主角陈豆（豆仔）重生回 2018 年高考前一个月，末世比他记忆中提前两年降临。
- **作者**：多年书虫，但自称**写作小白**——需要你主动引导、提供方案和判断，而不是只做记录员。
- **写作方式**：**agent 主笔，作者微调**。所以 canon 文件必须准确、完整，它们是 agent 写作的唯一依据。
- **创作初衷（作者原话要点）**：
  1. 这是作者**几个现实中真实损友**在末世中求生冒险的"幻想"故事。其他人物可以随意发挥，但**几个主要主角必须符合现实人物设定**，后续作者会继续补充他们的现实特质。
  2. 故事起点是现实世界突发末世；整体类似"灵气复苏"带来全球进化，**缓慢演化**，世界观逐渐变成"修仙玄幻世界"，到接近结尾才完成转变。**结局是主角几人从现实世界的普通人，成为修仙世界后世眼中"创世之初的传说"**，要有史诗感。

## 2. 已拍板的核心决策（速查；以 大纲.md 为准，有冲突以 大纲.md 为准）

- **本书是一部修仙世界的"前传"**：主线是**"秩序的崩塌与重建"**。主角几人因参与并深刻影响了秩序/规则的构建，成为**历史记载**中的人物（不是神话，不是信仰）。
- **结局画面**："秩序已成"——一切秩序建立、规则完善，恰好能衔接某部修仙小说的开头。
- **主角几人全员活到最后**（长寿由境界提升带来）。
- **时间跨度**：千年到万年量级。叙事密度越往后越疏：阶段一逐日逐夜地写，后面的阶段靠时间跳跃。
- **体量**：长篇，字数不重要，故事讲好最重要。
- **叙事人称**：贴着陈豆的第三人称限知（注意：既有正文里有商机/旺仔等分线视角，如何统一是**待讨论项**，见 WORKFLOW 路线图第 8 项）。
- **境界**：暂定共九阶；阶位颜色一阶紫、二阶蓝、三阶青、四阶绿，五阶起未定。
- **"清风"**：商机命名；是**精英小队**（核心几人到十人，战力很高），**不是大型幸存者组织**，**不会在阶段二成立**，成立时间更靠后。
- **阶段一《崩塌》**（约数月）：
  - 陈豆+选手线三个副本：**龙骨村**（丧尸/零散幸存者）→ **康安市区**（人类幸存者勾心斗角，粗糙小队组织）→ **秦岭**（大量进化兽）。三个副本分别展示崩塌的"个体 / 社会 / 自然"三个层面。
  - 主轴：陈豆（重生者）帮助选手（善良、刚成年、不适应）适应末世残酷。
  - 各人互相认定对方会先回夕海，这是行动的"主线任务"，但**不会**以夕海会合作为阶段一结尾。
  - 商机+胖子在**秦岭**与陈豆+选手阴差阳错地会合。到秦岭时几人约二阶巅峰~三阶初期。
  - 小雪被大鸟叼往秦岭是刻意埋的伏笔，秦岭副本呼应，但陈豆选手**不是为救小雪才走秦岭**（巧合），作用是继续完成选手的心理蜕变。
- 其他既有设定（"无隐藏世界观，只有起点与未来史"、18 件传说神器、铜剑成长为圣剑古宗、旺仔紫石=异能石的反套路处理等）见 [设定集.md](设定集.md)。

## 4. 与作者协作的约定（务必遵守）

1. **一次只问一个大的方面**，最多拆成 3 个小点；作者说过，问多了他回答会乱。
2. **先落盘，再提下一个问题**。作者回答后，先把结论写进对应 canon 文件，再继续。**绝不在没有真正写入文件的情况下说"已记录"**（上一个 session 犯过这个错，被发现后补写并向作者道歉）。写完可用 grep 核对。
3. 来源要标清：`作者拍板`（带日期）/ `【建议】` / `【待补充】`。没经作者确认的内容不要写成已定。
4. 新决定与旧内容冲突时，**在旧条目处标 ⚠️ 并注明"待重排"，不要静默覆盖**。
5. 作者是写作小白：提问时附上已知条件，必要时给一个草稿让他挑毛病，但不要替他做决定；他否定草稿是正常的，按他的反馈改。
6. 作者的真实朋友是主角原型：涉及主角性格的内容尽量向作者确认，鼓励他补充现实特质。
7. 修改已有正文走"改旧的"流程：先影响面分析师出报告，作者确认范围后才动手（纯代词替换这类零连带影响的小改动，作者可直接批准）。
8. 涉及 GitHub/账号/密码/密钥等操作要谨慎：不替作者输入密码，不改账号安全设置，推送到哪个仓库先确认。

## 6. 九个专家与配合方式

所有 SKILL.md 里的路径都**相对仓库根目录**。`.claude/skills/` 下的 skill 会在 Claude Code 工作目录为仓库根时自动被发现，可用 Skill 工具按名调用。

| skill 名 | 角色 | 写权限 |
|---|---|---|
| `outline-architect` | 大纲架构师：把作者的回答/新想法写成大纲条目 | `大纲.md` |
| `setting-keeper` | 设定管理员：世界观规则与名词 | `设定集.md` |
| `character-arc-keeper` | 人设弧光守护者：人物动机、现实特质、弧光 | `人物表.md` |
| `foreshadow-designer` | 伏笔/节奏设计师：钩子、高潮、伏笔埋收 | `伏笔清单.md` |
| `logic-auditor` | 逻辑校验官：只找矛盾，出报告 | 无 |
| `lead-writer` | 主笔：唯一能碰正文文字的角色 | `正文.md` |
| `archivist` | 归档员：收尾同步状态并留痕 | `变更记录.md` 等 |
| `brainstorm-novelist` | 资深小说家：纯讨论，给方向，不动文件 | 无 |
| `impact-analyzer` | 影响面分析师：改旧内容前出范围报告并等确认 | 无 |

**三种创作模式**（动笔阶段使用，详见 WORKFLOW 第三节）：
- ① 写新的：大纲架构师 → 设定/人设/伏笔（并行）→ 逻辑校验官 → 主笔 → 归档员
- ② 改旧的：影响面分析师（出报告、等作者确认）→ 对应专家（修订模式）→ 主笔（只改圈定范围）→ 归档员
- ③ 讨论灵感：资深小说家 → 灵感种子 → 交大纲架构师

**大纲完善阶段（当前）的配合**：主控担任提问者，每次一个大方面 → 作者回答 → 复述确认并指出隐含后果/冲突 → 同一轮内由大纲架构师写 `大纲.md`，涉及世界规则/人物/伏笔时同步写对应文件 → 下一个方面。每完成一个阶段做一次检查点：逻辑校验官通读 canon 出报告，作者决定是否改，归档员写 `变更记录.md`。大纲达到 WORKFLOW 2.6 的"可用"标准、作者明确说"可以开始写"之后，才进入动笔阶段。
