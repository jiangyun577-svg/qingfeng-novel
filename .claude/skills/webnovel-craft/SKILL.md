# 网文技法库

> 路径约定：本文所有文件路径均相对**仓库根目录**（含 README.md 的那一层），请把 Claude Code 的工作目录设为仓库根目录。

这不是一个会写文件的角色，而是一套**参考资料**。你在讨论剧情、规划副本、设计章末之前，先读对应的参考文件，用里面的方法检查自己的方案。

## 来源与许可

这些技法整理自两个公开的开源项目的文档（都是 MIT 协议）：
- [tianshiemo7/long-novelist-skill](https://github.com/tianshiemo7/long-novelist-skill)：钩子、章末悬念、情节结构、副本模板、大纲、伏笔、对话、爽点素材、末世与无限流素材。
- [zenstory-ai/oh-story-claudecode](https://github.com/zenstory-ai/oh-story-claudecode)：拆文方法、长篇写作的分层大纲与新增元素分级、多视角审稿、去AI味。

我们用自己的话重写，并按《末世清风》的需要裁剪和改写，**没有复制它们的脚本和大段原文**，也没有运行它们的任何代码。2026-10-22 整理。

其他角色按需读：伏笔设计师读 01、04；主笔读 06、08；逻辑校验官读 07。

## 使用原则

1. **技法是检查工具，不是模板。** 不要把方案套成公式，也不要因为技法书里有某个套路就硬塞。
2. **作者拍板优先。** 技法和作者已定的设定、文风冲突时，听作者的。
3. **先看本书的特色再选技法。** 《末世清风》的底色是"喜剧群聊 × 末世残酷"，主题是"秩序的崩塌与重建"，有多条线并行，有真实损友的人设。选技法时先问：这条能不能帮我们把这几个特点写得更足。
4. **用了技法要说出来。** 给作者的方案里，写明哪一步用了哪种钩子、哪种爽点，这样作者能评判，也能学到。
5. **不要用破折号"——"。** 这是作者明确的要求，写进这个库里的文字也一样。
